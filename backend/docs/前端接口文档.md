# 特殊教育课堂助手 V2 前端接口文档

本文档按当前后端代码与 `openapi.yaml` 0.12.0 生成，用于前端联调、Apifox 对照和接口走查。

云端同步目标：[特殊教育课堂助手 V2 前端接口文档](https://nankai.feishu.cn/wiki/XIhbwUYGGildJSkv7sSca0aMn8g)。后续接口契约更新应同时维护本文件、`openapi.yaml` 和该飞书文档。

项目级总接口入口见 [`../../docs/项目接口总文档.md`](../../docs/项目接口总文档.md)。其他同学新增接口时，应优先补充项目总接口文档，再按需要补充各自模块详细文档。

## 1. 基础约定

| 项目 | 内容 |
|---|---|
| 契约版本 | `0.12.0` |
| 本地 BASE_URL | `http://localhost:3000/api` |
| HTTPS 隧道 BASE_URL | `https://<cpolar 地址>/api`，由 `scripts/tunnel/start-cpolar-tunnel.cmd` 生成并验证 |
| 路径写法 | 下文路径均为相对 BASE_URL；例如 `GET /health` 的完整地址是 `GET /api/health` |
| 请求格式 | `Content-Type: application/json` |
| 响应格式 | `{ "code": 0, "message": "ok", "data": ... }` |
| 成功判断 | `code === 0` |
| 失败处理 | `code !== 0` 时前端展示 `message` |
| 白名单身份 | 除健康检查外，业务接口只接受 `X-Teacher-Id: t001/t002/t003` |
| 旧请求头 | `X-User-Id` 已停用 |

成功响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

错误响应示例：

```json
{
  "code": 40001,
  "message": "请求参数不合法",
  "data": null
}
```

## 2. 通用错误码

| code | 含义 |
|---:|---|
| `40001` | 请求参数不合法 |
| `40002` | 当前用户尚未选择当前学生 |
| `40101` | 缺少或无法识别白名单教师身份 |
| `40401` | 资源不存在，或资源不属于当前用户/当前学生 |
| `40901` | 资源状态冲突，例如重复分配训练目标 |
| `40902` | 删除前需要二次确认 |
| `50000` | 服务内部错误 |

## 3. 枚举值

| 枚举 | 可选值 |
|---|---|
| 用户角色 `role` | `RESOURCE_TEACHER` 资源教师；`SHADOW_TEACHER` 影子老师；`PARENT` 家长 |
| 学生性别 `gender` | `MALE` 男；`FEMALE` 女 |
| 随班汇总周期 `period` | `WEEKLY` 周记录；`MONTHLY` 月记录 |
| 学生评估周期 `period` | `DAILY` 日报；`WEEKLY` 周报；`MONTHLY` 月报 |
| 训练状态 `status` | `NOT_STARTED` 未开始；`IN_PROGRESS` 进行中；`COMPLETED` 已完成；`PAUSED` 暂停 |
| 训练目标类型 `goalType` | `STANDARD` 标准目标；`CUSTOM` 自定义目标 |
| 训练阶段 `phase` | `1`、`2`、`3` |

日期使用 `YYYY-MM-DD`，例如 `2026-07-17`。时间使用带偏移的 ISO 8601，例如 `2026-07-17T09:12:45+08:00`。

### 3.2 HTTPS 真机联调

真机预览不能使用 `localhost`，应先运行项目根目录的 cpolar 脚本：

```powershell
.\scripts\tunnel\configure-cpolar.cmd
.\scripts\tunnel\start-cpolar-tunnel.cmd
```

将启动脚本输出的 `https://.../api` 填入前端 `BASE_URLS.tunnel`。脚本会同时验证公网 `GET /api/health`，只有响应满足 `code === 0` 且 `data.status === 'UP'` 时才报告成功。cpolar 随机域名可能在每次启动后变化，前端不应把临时地址提交为生产配置。

## 5. 系统

### 5.1 服务健康检查

`GET /health`

不需要身份请求头，用于前端“测试后端连接”按钮，并正式替代 Day3 任务草案中的 `GET /api/test`，不再新增重复测试接口。

微信小程序联调示例：

```javascript
wx.request({
  url: 'http://localhost:3000/api/health',
  method: 'GET',
  success(res) {
    const body = res.data
    const connected = res.statusCode === 200
      && body.code === 0
      && body.data.status === 'UP'
    console.log('后端连接状态', connected, body.message)
  },
  fail(error) {
    console.error('后端连接失败', error)
  }
})
```

联合验收标准：微信开发者工具控制台输出连接成功，网络面板显示 HTTP 200，响应满足统一包体且 `data.status === 'UP'`。

响应 `data`：

```json
{
  "status": "UP"
}
```

### 7.11 保存完整详细记录

`PUT /behavior-records/{recordId}/details`

请求头：`X-Teacher-Id`

请求体：

```json
{
  "durationMinutes": 1,
  "stageCode": null,
  "antecedentText": "教师开始点名。",
  "behaviorDescription": "学生离开座位走向门口。",
  "consequenceText": "教师口头提示后返回。",
  "functionCode": "OTHER",
  "functionOtherText": "获得活动机会",
  "statusCode": "INDEPENDENT",
  "assistances": [
    {
      "code": "VERBAL_ASSISTANCE"
    }
  ],
  "assistanceResultText": "一次语言提示后完成。",
  "subBehaviorCodes": ["B001_S01"],
  "performanceSelections": [
    {
      "optionCode": "B001_P04",
      "customText": null
    }
  ]
}
```

响应 `data`：`BehaviorRecordDetail`

说明：

- A、B、C 均为自由文本。
- `functionCode` 可选值为 `ATTENTION`、`TANGIBLE`、`ESCAPE`、`SENSORY`、`OTHER`；选择 `OTHER` 时必须填写 `functionOtherText`，其他值时该字段必须为空。
- `statusCode` 可选 `INCOMPLETE`、`ASSISTED`、`INDEPENDENT`。显式选择优先；未传状态但勾选至少一种辅助方式时后端自动保存为 `ASSISTED`；快速记录初始为 `null`。
- 持续时间、行为环节、A、B、C、行为功能、辅助方式、辅助结果、子行为或表现状态至少填写一项；全部为空返回 `400`。
- `assistances` 可以省略、传 `null` 或空数组，后端均按未选择辅助方式处理。
- 选中的辅助方式只要求 `code`，`content` 可以省略、传 `null` 或空字符串。
- 保存成功后，`detailSaved` 永久为 `true`。
- `subBehaviorCodes` 和 `performanceSelections` 支持多选，选项必须属于当前主行为。
- 有 `parentSubBehaviorCode` 的表现状态必须同时选中对应子行为。
- 目录返回 `requiresCustomText=true` 时必须填写 `customText`；否则禁止填写。

辅助方式固定编码：

| 分组 | code | 名称 |
|---|---|---|
| 刺激内辅助 | `ADD_EXTERNAL_OBJECT` | 增加外在物品 |
| 刺激内辅助 | `CHANGE_TARGET_SIZE` | 改变目标物大小 |
| 刺激外辅助 | `FULL_BODY_ASSISTANCE` | 全身体辅助 |
| 刺激外辅助 | `HALF_BODY_ASSISTANCE` | 半身辅助 |
| 刺激外辅助 | `POSTURE_ASSISTANCE` | 姿势辅助 |
| 刺激外辅助 | `POSITION_ASSISTANCE` | 位置辅助 |
| 刺激外辅助 | `VERBAL_ASSISTANCE` | 语言辅助 |
| 刺激外辅助 | `DEMONSTRATION_ASSISTANCE` | 示范辅助 |
| 刺激外辅助 | `VISUAL_ASSISTANCE` | 视觉辅助 |

### 7.12 删除一条行为记录

`DELETE /behavior-records/{recordId}`

请求头：`X-Teacher-Id`

响应 `data`：`null`

说明：

- 前端根据 `detailSaved` 判断是否弹出确认框。
- 最近一条记录 `detailSaved = false` 时可直接删除。
- 最近一条记录 `detailSaved = true` 时先确认，再调用删除接口。

## 8. 学生评估

### 8.1 查询日/周/月概况和行为趋势

`GET /student-evaluation/statistics`

请求头：`X-Teacher-Id`

Query：

| 参数 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `period` | 是 | `DAILY` | `DAILY`、`WEEKLY`、`MONTHLY` |
| `referenceDate` | 是 | `2026-07-17` | 参考日期 |

响应 `data`：`StudentEvaluationStatistics`

说明：

- 统计数据来源于当前学生的随班记录。
- `DAILY` 与前一天比较，`WEEKLY` 与上一自然周比较，`MONTHLY` 与上一自然月比较。
- `UP` 表示次数上升，前端显示红色；`DOWN` 表示次数下降，前端显示绿色；`STABLE` 显示灰色。
- 上一周期次数为 0、本周期大于 0 时，`changePercent` 返回 `null`，趋势仍为 `UP`。
- `items` 包含当前周期或上一周期至少出现过一次的行为。
- 周统计的 `dailyTrends` 固定返回周一至周日 7 项；月统计的 `weeklyBreakdown` 按自然周动态返回，尚未到来的周不返回。
- `unclassifiedCount` 是尚未选择三态的快速记录数，不进入独立完成率分母。
- `trainingGoalCount` 统计已发生记录关联的全部标准目标去重数，不限于是否激活。

### 8.2 查询 ABC 行为功能分布

`GET /student-evaluation/abc-distribution`

Query：`period=DAILY|WEEKLY|MONTHLY`、`referenceDate=YYYY-MM-DD`。

固定返回 5 个功能项，无记录项 `count=0`；`totalCount` 和百分比仅以已保存详细记录且已选择行为功能的记录计算。

### 8.3 查询行为表现自由文本趋势

`GET /student-evaluation/behavior-description-trend`

Query：`period=WEEKLY|MONTHLY`、`referenceDate=YYYY-MM-DD`、可选 `limit`（默认 10，最大 50）。

按 trim 后完全一致的 `behaviorDescription` 分组。周统计返回 TOP N 次数；月统计返回 4–6 个自然周计数，并以第 1 周与最后一个有数据周比较生成 `UP`、`DOWN`、`STABLE`。

| `STAIRS` | 上下楼梯 | 65-75 |
| `QUEUE` | 排队 | 76-87 |
| `DINING` | 用餐 | 88-110 |
| `BREAK_TIME` | 课间休息 | 111-130 |
| `GROUP_CLASS` | 集体课 | 131-165 |
| `CUSTOM` | 自定义 | 无 |

### 9.2 搜索和筛选标准目标库

`GET /training-plan/library`

请求头：`X-Teacher-Id`

Query：

| 参数 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `keyword` | 否 | `老师` | 按目标名称模糊搜索 |
| `categoryCode` | 否 | `SCHOOL_CLASS_AWARENESS` | 按分类筛选 |

响应 `data`：`TrainingGoalLibraryItem[]`

### 9.3 查询当前学生已分配目标

`GET /training-plan/items`

请求头：`X-Teacher-Id`

Query：

| 参数 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `keyword` | 否 | `老师` | 按目标名称模糊搜索 |
| `categoryCode` | 否 | `GROUP_CLASS` | 按分类筛选 |
| `status` | 否 | `IN_PROGRESS` | 按训练状态筛选 |

响应 `data`：`TrainingPlanItem[]`

### 9.4 查询全部已激活目标进度

`GET /training-plan/goals-progress`

Query：`period=WEEKLY|MONTHLY`、`referenceDate=YYYY-MM-DD`。

响应按行为模块分组，返回当前学生全部已激活目标；无记录目标次数为 0。每条行为记录计入主行为关联的全部标准目标，不按子行为过滤。月统计额外返回 `weeks`。

### 9.5 查询标准目标关联行为记录

`GET /training-plan/goals/{standardNumber}/records`

Query：可选 `limit`，默认 10、最大 50。返回 `totalCount` 和按发生时间倒序的记录；`subBehaviors`、`performanceOptions` 均为数组，`performanceText` 可直接展示。目标编号不存在时返回 404。

### 9.6 激活标准目标

`POST /training-plan/items/standard`

请求头：`X-Teacher-Id`

请求体：

```json
{
  "assignments": [
    {
      "goalId": 101,
      "initialLevel": "C"
    },
    {
      "goalId": 102,
      "initialLevel": "D"
    }
  ]
}
```

响应 `data`：`TrainingPlanItem[]`

说明：

- `goalId` 是标准目标库中的数据库 ID，不是 `standardNumber`。
- `initialLevel` 为学期初等级，当前等级默认等于学期初等级。
- 阶段默认 `1`，状态默认 `NOT_STARTED`。
- 同一标准目标不能重复分配给同一学生。

### 9.7 创建自定义目标

`POST /training-plan/items/custom`

请求头：`X-Teacher-Id`

请求体：

```json
{
  "goalText": "能在课前主动准备学习用品",
  "initialLevel": "C"
}
```

响应 `data`：`TrainingPlanItem`

说明：自定义目标统一归入 `CUSTOM` 分类，只属于当前学生。

### 9.8 即时更新等级、阶段或状态

`PATCH /training-plan/items/{itemId}`

请求头：`X-Teacher-Id`

请求体为局部更新，至少传一个字段：

```json
{
  "currentLevel": "B",
  "phase": 2,
  "status": "IN_PROGRESS"
}
```

响应 `data`：`TrainingPlanItem`

说明：`initialLevel` 只读，不通过本接口修改。

### 9.9 取消分配或删除自定义目标

`DELETE /training-plan/items/{itemId}`

请求头：`X-Teacher-Id`

Query：

| 参数 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `confirmed` | 否 | `true` | 已产生进度时，前端二次确认后传 `true` |

响应 `data`：`null`

删除规则：

- 标准目标：取消当前学生的分配。
- 自定义目标：永久删除该自定义目标。
- 已产生进度时，首次删除返回 `40902`；前端确认后使用 `confirmed=true` 重试。
