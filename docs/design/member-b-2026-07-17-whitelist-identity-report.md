本项任务来自 `7.17任务.md` 中成员 B 的“白名单伪登录”要求，以及后续前后端联调约定：

- 前端每个业务请求只携带 `X-Teacher-Id`。
- 后端直接根据 `X-Teacher-Id` 识别当前教师，不再使用 token。
- 教师 ID 白名单暂定为 `t001`、`t002`、`t003`。
- 统一响应包体继续使用 `{ code, message, data }`。
- 缺少或无法识别教师身份时返回 HTTP 401，业务错误码为 `40101`。

### 3.2 后端身份解析

- 新增集中式教师身份解析逻辑。
- 所有业务接口统一从 `X-Teacher-Id` 解析当前教师。
- 已移除业务接口对 `X-User-Id` 的兼容。
- `GET /api/health` 仍保持匿名访问，用于前端“测试后端连接”。
- 严格限制教师 ID 格式：
  - `t001` 可用
  - `T001` 不可用
  - `t999` 不可用
  - 只传 `X-User-Id` 不可用
- 缺少、格式错误或白名单外的教师 ID，统一返回：

```json
{
  "code": 40101,
  "message": "未识别的教师身份",
  "data": null
}
```
