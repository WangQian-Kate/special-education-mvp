# 成员 B 正式数据库创建与验收

> 历史验收记录：本文描述旧 V0.3 数据库。V2 将按 `member-b-v2-data-model.md` 重构空业务表，并保留现有用户、学生和绑定数据。

## 1. 实施范围

本次实施把已经确认的数据模型落到本机 MySQL 8.0，覆盖四个一级页面：随班记录、训练计划、学生评估和我的。

实施遵循以下边界：

- 只创建前端和任务文档已经明确的数据字段。
- 不增加 `created_at`、`updated_at` 等未确认字段。
- 不创建微信登录、AI 分析结果、报告快照、PDF 或静态功能入口表。
- 课程行为配置暂时按课程区分，不增加学生维度。
- SQL 脚本不包含 `DROP`、`TRUNCATE` 或清空数据操作。

## 2. 数据库对象

数据库名为 `special_ed_assistant`，字符集为 `utf8mb4`，排序规则为 `utf8mb4_0900_ai_ci`。

正式结构共 15 张表：

| 模块 | 表 | 用途 |
|---|---|---|
| 我的 | `app_user` | 当前教师或家长 |
| 我的 | `student` | 学生信息 |
| 我的 | `app_user_student` | 用户与学生绑定 |
| 基础字典 | `course_type` | 课程字典 |
| 基础字典 | `environment_type` | 环境字典 |
| 基础字典 | `antecedent_type` | A 前因字典 |
| 基础字典 | `behavior_type` | B 行为字典 |
| 基础字典 | `consequence_type` | C 后果字典 |
| 基础字典 | `assistance_type` | 辅助方式字典 |
| 随班记录 | `observation_session` | 观察周期 |
| 随班记录 | `behavior_record` | 行为明细 |
| 随班记录 | `behavior_record_assistance` | 行为与多选辅助方式关联 |
| 随班记录 | `course_behavior_config` | 课程对应的观察行为 |
| 训练计划 | `student_training_plan` | 学生训练计划 |
| 学生评估 | `teacher_evaluation` | 日、周、月教师评价 |

表之间建立 19 个外键。行为记录通过联合外键关联观察周期及学生，避免把行为记录写到不属于该学生的观察周期中。

## 3. 关键业务约束

- 用户角色仅允许 `RESOURCE_TEACHER`、`SHADOW_TEACHER`、`PARENT`。
- 快速行为记录只要求 B 行为；A 前因和 C 后果允许为空。
- 每次快速记录默认 `frequency = 1`，且频次必须大于 0。
- 辅助方式通过关联表支持多选。
- 观察时长必须大于 0。
- 教师评价的结束日期不得早于开始日期。
- `scene` 不重复保存，统一由观察周期的 `environment_code` 表示。
- “本周期行为备注”使用 `period_behavior_remark` 字段。

## 4. 初始化数据

`backend/sql/seed.sql` 初始化：

- 演示教师 1 名、演示学生 1 名及绑定关系 1 条。
- 课程 11 项。
- 环境 9 项。
- A 前因 1 项。
- B 行为 12 项。
- C 后果 1 项。
- 辅助方式 7 项。
- 语文和体育课程行为映射 11 条。

不初始化虚假的行为记录、训练计划或教师评价。

## 5. 应用账号权限

本机应用账号为 `special_ed_app@localhost`，只授予：

- `SELECT`
- `INSERT`
- `UPDATE`
- `DELETE`

应用账号没有 `CREATE`、`ALTER`、`DROP`、`GRANT` 等结构或管理权限。应用密码只通过 `DB_PASSWORD` 环境变量传入，不写入 SQL、配置文件或文档。

## 7. 后续跨成员事项

以下事项不属于本次数据库创建范围，相关功能启动前需要与前端或成员 C 确认：

- 课程行为配置是否需要按学生独立维护。
- 训练计划等级的完整取值和含义。
- 课程、环境及 A/B/C 字典最终全集。
- AI 分析结果、报告快照和 PDF 是否持久化。
- 离线同步是否需要客户端唯一标识。
- 学生年龄后续是否改为出生日期。
